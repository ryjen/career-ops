# Synthetic-data policy

Public examples and fixtures must be independently invented for a documented behavior scenario.

Invent all identities, organizations, roles, URLs, requisitions, locations, compensation, dates, application states, evidence, paths, and provider metadata. Do not rename, lightly perturb, summarize, hash, or combine a real private record when the result remains distinctive or re-identifiable.

Future fixture metadata must record:

- scenario purpose;
- synthetic origin;
- reviewer and review state;
- prohibited resemblance findings or reviewed exceptions.

Unknown fixture origin blocks release.
